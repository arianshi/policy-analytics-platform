# Data sources

Three sources, three formats, two of them real APIs. Everything marked **real** was fetched on **2026-10-30** with the platform's own adapters (`scripts/refresh_snapshots.py`) and is stored with provenance in `backend/data/snapshots/manifest.json` (URL, retrieval time, byte size, SHA-256).

## 1. Ministry of Manpower via Data.gov.sg - **real**, CSV

* **API:** Data.gov.sg v1 download flow: `GET https://api-open.data.gov.sg/v1/public/api/datasets/{datasetId}/poll-download` → JSON with a short-lived presigned S3 URL (`status: DOWNLOAD_SUCCESS`) → `GET` the CSV. The adapter polls until the download is ready. No API key is required for these public datasets.
* **Licence:** Singapore Open Data Licence v1.0 (attribution is kept in every citation).

**Practical findings while integrating (all handled in code):**
* **HTTP 429.** The API rate-limits after a handful of requests. The adapter retries with exponential backoff honouring `Retry-After`; the extraction agent retries once more, then falls back to the snapshot. This happened *for real* in a live run: 5 of 10 datasets were rate-limited, 4 were recovered through snapshot fallback, and the report was marked "Completed with fallbacks" (6 datasets live, 4 snapshot, 18.6 s).
* **User agent.** An early exploratory script using Python's default `urllib` user agent got empty responses from the catalog API while `curl` worked; sending a descriptive `User-Agent` fixed it (cause not confirmed - most likely edge filtering), so the adapters always send one.
* **Messy values:** `-` as a suppression marker (retrenchments), and a **conflicting duplicate row in the source itself** (Construction 2023 total wage change appears as both 4.2 and 5.5). The platform excludes both and reports them rather than picking one.
* **Label inconsistency:** industries are lower-case in some tables and Title-Case with dropped ampersands in others (`Food  Beverage Services`); sub-industries (48 labels) are outside the ontology and are dropped *and disclosed* in the data-quality log.

## 2. Department of Statistics (SingStat) Table Builder - **real**, JSON API

* **API:** `GET https://tablebuilder.singstat.gov.sg/api/table/tabledata/M015731?timeFilter=2000,2001,…` (comma-separated filter; repeated parameters are rejected). Table search: `/api/table/resourceid?keyword=…&searchOption=title`.
* **Table:** `M015731` *Gross Domestic Product At Current Prices, By Industry (SSIC 2020), Annual* (S$ million), 2000-2025, 355 rows.
* **Parsing:** nested `Data.row[].columns[{key,value}]` → long format. A response without `Data.row` (HTTP 200 with an error body) raises `SchemaError`.
* **Harmonisation:** SingStat labels (`Finance & Insurance`, `Real Estate`, `Public Administration & Defence` + `Education`) are mapped to the same sector ids as MOM's; the two public-sector components are summed. This enables the cross-source **value-added-per-worker** analysis (SingStat GDP ÷ MOM employed residents).

## 3. Internal programmes extract - **MOCK**, Excel

`backend/data/internal/tech_programmes.xlsx`, generated by `scripts/generate_internal_mock.py` (fixed seed; 201 rows: 8 years × 5 programmes × 5 sectors, 2018-2025). It stands in for an internal database to demonstrate Excel ingestion, free-text sector resolution and data-quality handling, and is **labelled MOCK** in the catalog, provenance, citations, charts, narrative (the verifier *requires* the label) and the UI. Injected defects (documented so tests can assert them): one `2O22` year, one blank, one `n/a`, one negative completion, two exact duplicate rows, one 9× outlier, one missing cell, and sector label variants (`ICT`, `Info-comm`). It must never be cited as real data.

## 4. Fetch strategy and error handling

```
acquire(key):  fault-injection check → [LIVE_DATA=false → snapshot, not degraded]
               → disk cache (TTL 24 h) → live fetch (retry/backoff, Retry-After)
               → raises DataSourceError(code ∈ unavailable | rate_limited | timeout | not_found | schema, retryable)
Extraction agent decides:  retry once if retryable → use_snapshot (marks degraded) → skip if optional → fail if required
```
Every dataset carries `Provenance(mode = live | cache | snapshot | internal, degraded, retrieved_at, url, licence)` into the report's citations. Snapshots are **real past downloads**, never fabricated stand-ins; if the live source is unreachable the user is told the figures may lag the latest release.

**Fault injection** (for demos/tests; disable with `ALLOW_FAULT_INJECTION=false`): `source:<mom|singstat|internal>[:unavailable|rate_limited|timeout|schema]`, `llm:<provider|*>`.

## 5. Why not SingStat for employment by industry, or other sources?
SingStat's employment tables are coarser than MOM's industry-level labour-force data, and MOM publishes the series needed (vacancies, recruitment, resignations, retrenchments, wages) at industry level through Data.gov.sg. IMDA's "Employed ICT Manpower" dataset was evaluated but ends in 2018, so it cannot support a 2020-2024 question. The adapter/catalog design (`DatasetSpec` + a normaliser per source) makes adding quarterly series or other agencies' datasets a configuration-sized change.

## 6. Refreshing the snapshots
`make refresh-data` (≈1 minute; paced because of the rate limit). Provenance in `manifest.json` is rewritten; tests assert every catalog entry has a snapshot with `retrieved_at`, `sha256` and `source_url`.
